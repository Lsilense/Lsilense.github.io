💬 智能客服系统

📅 2026 年 6 月 🏷️ LLM · RAG · LangChain

项目背景

传统客服系统面临响应慢、知识更新滞后、人力成本高等问题。本项目旨在基于大模型技术构建一套企业级智能客服系统，实现 7×24 小时自动应答，同时保留人工兜底机制。系统已在电商场景落地，日均处理 5000+ 对话。

系统架构

智能客服系统采用分层架构设计，分为接入层、理解层、知识层和响应层四个主要模块：

接入层

统一接入网关，支持多渠道接入（Web、微信、APP），通过 WebSocket 实现实时通信。会话管理模块负责用户身份识别、对话上下文维护和会话生命周期管理。

理解层

基于大模型的意图识别与情感分析模块。用户输入首先经过意图分类器，判断用户的核心诉求（售前咨询、售后问题、技术故障等）。同时进行情感分析，识别用户的急迫度和情绪状态，对高优先级对话进行标记。

# 意图识别示意
INTENT_PROMPT = """根据用户输入判断意图类别：
- 售前咨询：产品信息、价格、规格
- 售后问题：退换货、物流、投诉
- 技术支持：使用问题、故障报修
- 其他

用户：{user_input}
意图："""

def classify_intent(user_input):
    response = llm.generate(INTENT_PROMPT.format(user_input=user_input))
    return parse_intent(response)

知识层

知识层是系统的核心，采用 RAG（Retrieval-Augmented Generation）架构：

  • 向量知识库：基于 Milvus 存储 FAQ、产品文档、工单记录等向量化知识
  • 混合检索：结合向量检索与关键词检索（BM25），提升召回率
  • 知识图谱：构建产品关系图谱，支持多跳推理查询
  • 实时知识更新：运营后台可实时新增或修改知识条目，无需重新索引

响应层

基于 LangChain 构建的 LLM 推理链，包含以下组件：

  • 对话管理：维护多轮对话的上下文窗口，支持指代消解
  • 检索增强：从知识库检索相关信息，注入 Prompt 作为参考上下文
  • 安全过滤：基于内容安全策略过滤不当输出，支持敏感词拦截
  • 兜底机制：当模型置信度低于阈值时，自动转接人工坐席
# LangChain 推理链示意
from langchain.chains import RetrievalQA
from langchain.vectorstores import Milvus

qa_chain = RetrievalQA.from_chain_type(
    llm=llm,
    chain_type="stuff",
    retriever=vector_store.as_retriever(
        search_type="mmr",
        search_kwargs={"k": 5, "fetch_k": 20}
    ),
    return_source_documents=True
)

# 执行问答
result = qa_chain({"query": user_input})
answer = result["result"]
sources = result["source_documents"]

关键特性

多轮对话

系统维护完整的对话上下文，支持上下文相关的问题追问和指代消解。例如用户问"这个多少钱"，系统能根据历史对话判断具体指向哪个商品。

工单自动生成

当用户问题需要线下处理时，系统自动生成标准工单，包含问题摘要、用户信息、会话记录等字段，推送到工单系统。

人工坐席辅助

转接人工后，系统为坐席提供实时建议回答和相关知识推荐，帮助坐席快速响应用户。坐席可直接引用或修改系统建议的答案发送给用户。

数据分析看板

提供实时数据看板，监控对话量、解决率、平均响应时间、用户满意度等核心指标，辅助运营决策。

总结

该智能客服系统已在生产环境稳定运行，日均处理超过 5000 次对话请求，自动解决率达 75%，平均响应时间缩短至 3 秒以内。通过 RAG 架构有效解决了大模型知识更新的问题，同时人工兜底机制确保了服务质量。后续计划引入多模态能力，支持图片识别和语音交互。
