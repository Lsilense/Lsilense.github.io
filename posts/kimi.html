Kimi Chat 技术解析：超长上下文奠基者

📅 2026 年 6 月 14 日 🏷️ Kimi

引言

2023 年 10 月，月之暗面（Moonshot AI）发布了 Kimi Chat——一款以超长上下文窗口为核心卖点的大语言模型产品。在 GPT-4 标准 32K、Claude 100K 的年代，Kimi 以 128K 上下文窗口直接拉高了行业标杆，随后又扩展至 200 万 token。Kimi Chat 的成功不仅验证了长上下文技术的实用性，也为后续 K 系列模型奠定了技术基础。

本文作为 Kimi 系列四部曲的第一篇，聚焦 Kimi Chat 奠基期的核心技术：Dense Transformer 架构、Full Attention 与 Ring Attention 分布式训练、Mooncake 推理架构，以及位置编码与长度外推方案。

模型架构

Kimi Chat 采用标准的 Dense Transformer 架构，使用 Full Attention 机制。月之暗面未公开发布 Kimi Chat 的详细技术报告，其架构信息主要来自 Mooncake 论文和第三方分析。核心特征包括：

  • 架构类型：Dense Decoder-only Transformer
  • 上下文长度：初始 128K，后扩展至 200 万 token
  • 注意力机制：标准 Full Attention（完整自注意力）
  • 优化器：AdamW
  • 位置编码：RoPE（Rotary Position Embedding）

在那个阶段，Dense 架构仍是主流选择。Kimi 没有追求参数规模的竞赛，而是将工程重心放在了如何使超长序列的注意力计算成为可能——这形成了 Kimi 最核心的技术壁垒。

Ring Attention：分布式长上下文训练

训练 128K 乃至更长上下文的模型面临一个根本性挑战：标准 Full Attention 的计算和显存复杂度均为 $O(L^2)$，随序列长度二次增长。单 GPU 无法承载超长序列的注意力计算。

Ring Attention 是对 Bloom's Ring 通信模式在注意力计算上的创新应用。其核心思想是将长序列均匀分布在多 GPU 上，每个 GPU 持有序列的一部分，并通过环形通信模式逐块完成完整的注意力计算。

设序列长度为 $L$，$P$ 个 GPU 参与计算，每个 GPU 持有长度为 $L/P$ 的子序列。在每个通信轮次中，GPU 计算本地 Query 与当前持有的 KV Block 之间的注意力分数，然后将 KV Block 传递给环形拓扑中的下一个 GPU，同时从上一个 GPU 接收新的 KV Block：

$$ \text{Attn}_{\text{GPU}_i}^{(t)} = \text{Softmax}\left( \frac{\mathbf{Q}_i \mathbf{K}_i^{(t)\top}}{\sqrt{d_h}} \right) \mathbf{V}_i^{(t)}, \quad t = 1, \dots, P $$ $$ \text{Attn}_{\text{GPU}_i}^{\text{final}} = \sum_{t=1}^{P} \text{Attn}_{\text{GPU}_i}^{(t)} $$

经过 $P$ 轮通信后，每个 GPU 都获得了全序列的注意力计算结果。计算与通信通过流水线方式重叠，使得额外通信开销最小化。这种方式使得注意力计算的显存需求从 $O(L^2)$ 降低为 $O(L^2 / P)$，使超长序列的端到端训练成为可能。

# Ring Attention 示意
def ring_attention(q_local, k_ring, v_ring, comm, num_rounds):
    # q_local: 本设备持有的 Query 块
    # k_ring, v_ring: 初始 KV 块（本设备的部分）
    attn_output = 0
    for _ in range(num_rounds):
        local_scores = q_local @ k_ring.T
        local_attn = softmax(local_scores) @ v_ring
        attn_output += local_attn
        # 传递给下一个设备，接收上一个设备的数据
        k_ring = comm.send_recv(k_ring)
        v_ring = comm.send_recv(v_ring)
    return attn_output

分布式训练拓扑

Kimi 的整体训练采用多种并行策略的组合：

  • 数据并行（Data Parallelism）：多个模型副本在不同数据分片上独立计算梯度
  • 张量并行（Tensor Parallelism）：单层内的矩阵运算拆分到多 GPU
  • 序列并行（Sequence Parallelism）：结合 Ring Attention 将长序列分布到列内 GPU

这种多层次并行策略使得 Kimi 能够在数千 GPU 集群上高效训练超长上下文模型。

Mooncake：以 KVCache 为中心的解耦推理架构

Kimi 在推理侧的核心基础设施是 Mooncake（arXiv:2407.00079），一个以 KVCache 为中心的分离式 LLM 推理服务架构。Mooncake 的设计出发点是一个关键观察：长上下文推理时，KVCache 的存储成本正在成为瓶颈。

Prefill 与 Decode 分离

Mooncake 将推理过程划分为两个物理解耦的阶段：

  • Prefill Pool：专门处理 Prompt 编码阶段，计算密集且对延迟敏感
  • Decode Pool：专门处理 Token 生成阶段，需要大量内存容纳 KVCache

这种分离设计避免了传统架构中 Prefill 与 Decode 争抢同一 GPU 资源的冲突，允许对两个阶段独立进行资源标度。

KVCache 分层存储

Mooncake 建立了 GPU HBM → CPU DRAM → SSD 的三级 KVCache 存储体系：

  • L1 - GPU HBM：容量最小（~80GB），延迟最低，存放活跃请求的 KVCache
  • L2 - CPU DRAM：容量中等（~2TB），通过 RDMA 快速访问，存放等待恢复的 KVCache
  • L3 - SSD：容量最大（~数十 TB），存放历史 KVCache，换入延迟较高但可批量预取

全局调度器（Moonshot Scheduler）根据优先级和 KVCache 的访问模式决定数据在各层之间的迁移策略，使得长上下文推理的吞吐得到显著提升。

位置编码与长度外推

支持从 128K 到 200 万 token 的上下文扩展，不仅仅依赖 Ring Attention，还需要位置编码层面支持长度外推。

Kimi 采用 RoPE（Rotary Position Embedding） 作为位置编码方案。RoPE 将位置信息通过旋转矩阵注入 Query 和 Key 的向量表示中：

$$ \mathbf{q}_m = \mathbf{W}_Q \mathbf{x}_m \cdot e^{im\theta}, \quad \mathbf{k}_n = \mathbf{W}_K \mathbf{x}_n \cdot e^{in\theta} $$ $$ \langle \mathbf{q}_m, \mathbf{k}_n \rangle = \text{Re} \left[ (\mathbf{W}_Q \mathbf{x}_m)^* (\mathbf{W}_K \mathbf{x}_n) e^{i(m-n)\theta} \right] $$

RoPE 的注意力分数只依赖于相对位置 $m-n$，这一性质天然有利于长度外推。Kimi 在此基础上结合了以下技术实现从 128K 到 200 万 token 的扩展：

  • NTK-aware 插值：通过调整 RoPE 的 base frequency，使位置编码在高频段保持分辨率、在低频段扩展范围
  • 渐进式训练：从较短上下文起步，在训练过程中逐步增加序列长度，使模型逐步适应更长的依赖关系
  • 方法结合：In Context 时通过对模型 RoPE 基频进行微调，外推至训练时未见的超长位置

长上下文检索能力

Kimi Chat 的「大海捞针」（Needle-in-a-Haystack）测试表现是当时的行业标杆。该测试在一个超长文档中嵌入一条无关事实，询问模型是否能准确找到——Kimi 在 128K 乃至 200 万 token 测试中保持了接近 100% 的检索准确率。

这一能力不仅依赖于注意力机制本身，也得益于训练阶段的刻意设计：在长上下文持续训练阶段，模型被训练在超长输入中关注关键信息，而非平均分布注意力——训练数据中包含大量需要「从长文本中找到特定事实」的样本。

总结

Kimi Chat 奠基期确立了月之暗面在大模型领域的核心技术路线：以超长上下文为核心竞争力，以Ring Attention解决训练长序列的显存瓶颈，以Mooncake解决长上下文推理的部署挑战。这些核心技术在后来的 K1.5、K2、K2.5 中不断演进和深化。

Kimi Chat 时代的模型规格并未公开详细技术报告，但工程层面的基础设施积累——从分布式训练拓扑到推理服务架构——使得月之暗面能够在后续迭代中快速推进至万亿参数 MoE 和多模态智能体的前沿。
