Kimi K2 技术解析：万亿参数 MoE 与 MuonClip 优化器

📅 2026 年 6 月 14 日 🏷️ Kimi

引言

2025 年 7 月，月之暗面发布了 Kimi K2——一款基于 MoE 架构的万亿参数级模型。这是 Kimi 系列从 Dense 架构到稀疏架构的根本性转型：总参数 1.04T，激活参数 32B，384 个专家，配合 MLA 注意力和 MuonClip 优化器。15.5T tokens 的训练全程零 Loss Spike。

K2 在架构层面的三项核心创新使其在 Agent 任务上表现尤为突出：MuonClip（Muon + QK-Clip）解决了 Muon 优化器在超大规模训练中的注意力爆炸问题；MLA 注意力机制将 KV Cache 压缩到极致；Sparsity Scaling Law 为超大规模 MoE 的稀疏度选择提供了理论指导。本文将全面解析这三项创新及 K2 的训练基础设施。

K2 是 Kimi 系列中第一个采用 MLA 注意力机制的模型——Moonshot 与 DeepSeek 都独立走到了 MLA 或类 MLA 的设计方向，说明低秩 KV 压缩在超大规模 MoE 上已经成为共识级技术选择。

核心创新一：MuonClip 优化器

K2 选择了 Muon 作为基础优化器。Muon 的核心是通过正交化操作使梯度更新方向更接近自然梯度，在大规模 Transformer 训练中展现出比 AdamW 更快的收敛速度。但 Muon 在超大规模训练一个已知问题：注意力 Logits 爆炸。

在使用 Muon 训练大模型时，QK 点积的数值在训练过程中可能增长到 1000 以上，导致 softmax 后的注意力分布坍缩到 one-hot，梯度信号消失。K2 提出的 QK-Clip 方案优雅地解决了这个问题：

$$ S^h_{\text{max}} = \frac{1}{\sqrt{d}} \max_{i,j} \mathbf{Q}^h_i \mathbf{K}^{h\top}_j $$

如果 $S^h_{\text{max}} > \tau$（阈值设为 100），则缩放第 $h$ 个注意力头的参数：

$$ \gamma \leftarrow \frac{\tau}{S^h_{\text{max}}}, \quad \mathbf{W}^h_{qc} \leftarrow \mathbf{W}^h_{qc} \cdot \sqrt{\gamma}, \quad \mathbf{W}^h_{kc} \leftarrow \mathbf{W}^h_{kc} \cdot \sqrt{\gamma}, \quad \mathbf{W}^h_{qr} \leftarrow \mathbf{W}^h_{qr} \cdot \gamma $$

QK-Clip 的核心洞察在于：不是直接 Clip 梯度或 Logits 值，而是等比例缩放低秩压缩矩阵的权重，从根本上限制了 QK 点积的数值范围。

  • 训练早期，Logits 被控制在 100 以内，防止训练不稳定
  • 随着训练推进，模型学会更均衡的注意力分布，Logits 自然回落到正常范围
  • 全程 15.5T tokens 零 Loss Spike
# QK-Clip 核心逻辑
def qk_clip(q_proj, k_proj, q_restore, head_dim, threshold=100):
    # 计算当前最大 QK logits
    max_logits = compute_max_qk_logits(q_proj, k_proj)
    if max_logits > threshold:
        scale = threshold / max_logits
        sqrt_scale = scale ** 0.5
        # 缩放低秩压缩矩阵（不破坏 MLP 参数）
        q_proj *= sqrt_scale
        k_proj *= sqrt_scale
        q_restore *= scale
    return q_proj, k_proj, q_restore

核心创新二：MLA 注意力机制

Kimi K2 采用 Multi-head Latent Attention (MLA)，与 DeepSeek-V3 的设计思路一致。MLA 的核心思想是对 Key 和 Value 进行低秩联合压缩，将完整的 K/V 矩阵投影到低维隐空间中：

$$ \mathbf{k}^C_t = \mathbf{W}_{DK} \mathbf{h}_t, \quad \mathbf{v}^C_t = \mathbf{W}_{DV} \mathbf{h}_t $$ $$ \mathbf{k}_t = \mathbf{W}_{UK} \mathbf{k}^C_t, \quad \mathbf{v}_t = \mathbf{W}_{UV} \mathbf{v}^C_t $$

推理时仅缓存压缩后的 $(\mathbf{k}^C_t, \mathbf{v}^C_t)$ 而非完整的 K/V，使 KV Cache 的存储从 $2 \times n_h \times d_h$ 降至 $2 \times d_c$（其中 $d_c$ 是压缩隐空间维度，通常为 512，远小于 $n_h \times d_h$）。在 K2 的 1T 参数 + 128K 上下文场景下，MLA 带来的 KV Cache 节省是万亿参数模型得以在合理显存成本下部署的关键。

核心创新三：Sparsity Scaling Law

K2 在 MoE 架构设计中首次系统性地研究了稀疏度（Sparsity）对训练效果的影响。稀疏度定义为：

$$ \text{Sparsity} = \frac{N_{\text{total experts}}}{N_{\text{activated experts}}} $$

关键发现：在固定激活参数量（恒定 FLOPs）的条件下，增加总专家数（提高稀疏度）持续降低训练和验证 Loss。具体效果：

  • Sparsity 48（384 专家 / Top-8）相比 Sparsity 8 在不同计算量下分别实现了 1.69×、1.39×、1.15× 的 FLOPs 节省
  • 这一规律的线性扩展趋势表明：在固定激活参数下增加路由专家总数，模型能力可以持续提升
  • K2 最终选择 Sparsity 48 = 384/8 作为工程实现上的最优平衡点

此外，K2 还有一个有趣的发现：将注意力头数与层数设为相等可以额外降低 0.5%-1.2% 的验证 Loss。

预训练数据工程

K2 在 15.5T tokens 的预训练数据上采用了精细化的数据工程：

  • Web Text：沿袭 k1.5 的过滤方法论
  • Code：加强质量验证流水线
  • Mathematics：采用 SwallowMath 方法，将数学内容重写为「学习笔记」风格，并做了多语言翻译
  • Knowledge：采用 WRAP 风格的合成重写框架，对知识类数据进行风格和视角多样性的重写

知识数据的重写框架引入了一个关键机制：逐块自回归生成（Chunk-wise Autoregressive Generation）。将长文档分割为块，每块独立重写后拼接，并通过保真度验证管线确保事实完整性不被破坏。

RL 训练与 Agent 能力

K2 在 RL 训练阶段沿用 k1.5 的策略优化算法，并针对 Agent 场景做了专门增强：

$$ \mathcal{L}_{\text{RL}}(\theta) = \mathbb{E}_{x \sim \mathcal{D}} \left[ \frac{1}{K} \sum_{i=1}^{K} \left( r(x,y_i) - \bar{r}(x) - \tau \cdot \log \frac{\pi_{\theta}(y_i|x)}{\pi_{\text{old}}(y_i|x)} \right)^2 \right] $$

新增设计：

  • Budget Control：对不同任务类型设定不同的 Token Budget，超限截断并施加惩罚
  • Agentic Rollout：引入专用环境服务器，支持大量并发 Agent Rollout

训练基础设施

K2 的分布式训练采用了多层次并行策略组合：

  • Pipeline Parallelism (PP)：带有 virtual stages 的流水线并行
  • 16-way Expert Parallelism (EP)：专家并行
  • ZeRO-1 Data Parallelism：优化器状态分片

256 GPU 组成一个模型并行组，每 GPU 持有约 30GB 参数状态。EP all-to-all 通信通过 interleaved 1F1B 调度实现计算-通信重叠。此外还采用了激活值 CPU offload（通过 copy engine 流式 offload/onload）和分布式 checkpoint 引擎（支持 1T 模型参数的逐参数流水线更新）。

总结

Kimi K2 是一次从 Dense 到 MoE 的全面升级。MuonClip 优化器解决了 Muon 在超大规模训练中的稳定性问题；MLA 注意力提供了高效的 KV 压缩；Sparsity Scaling Law 为 MoE 设计提供了理论指导。K2 以 MIT 协议完全开源，是 Kimi 系列从纯文本推理走向 Agent 时代的关键里程碑。
