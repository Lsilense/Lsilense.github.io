vLLM 技术解析：高性能 LLM 推理引擎

深入解析 vLLM 推理引擎的核心技术：PagedAttention 显存管理实现近零浪费、Continuous Batching 动态调度、FlashAttention 加速内核、多级量化支持，以及 Qwen 全系列模型的推理部署实践。

📄 来源：Efficient Memory Management for Large Language Model Serving with PagedAttention · SOSP 2023 · arXiv:2309.06180 · GitHub: vllm-project/vllm

一、背景与简介

大语言模型（LLM）的推理服务面临一个核心挑战：KV Cache 显存管理。每个请求的 KV Cache 占用随序列长度动态增长，传统方法需要预先分配最大长度的连续显存空间，导致严重的内部碎片和外部碎片——显存利用率仅 20-40%。同时，请求的到达和完成不同步，批处理大小受限于碎片化的显存池，无法充分利用 GPU 算力。

vLLM 由 UC Berkeley Sky Computing Lab 开发（SOSP 2023），是当前最广泛使用的开源 LLM 推理引擎之一，GitHub 星标超过 82,000。其核心创新 PagedAttention 借鉴操作系统虚拟内存分页机制，将 KV Cache 按固定大小的块（Block）管理，实现了近零浪费的显存利用和请求间 KV Cache 共享，吞吐量相比 FasterTransformer 和 Orca 提升 2-4 倍。

2.1 PagedAttention 核心原理

PagedAttention 是 vLLM 最核心的架构创新。传统 Attention 机制中，KV Cache 以连续显存存储，每个请求预分配最大长度的空间。PagedAttention 将 KV Cache 切分为固定大小的 Block（典型 16 或 32 个 Token），通过 Block Table 进行逻辑到物理地址的映射：

  • 按需分配：只分配已生成 Token 所需的 Block，消除预分配浪费
  • 非连续存储：Block 可存放在任意物理地址，消除外部碎片
  • Block 级共享：相同前缀的请求共享 Block（如 System Prompt 缓存），减少重复存储
  • Copy-on-Write：Beam Search 等场景共享父序列 Block，仅在写入时复制

在 Attention 计算时，PagedAttention 通过 Block Table 索引将非连续的 KV Block 高效加载到 GPU SRAM 中计算。这使得 KV Cache 利用率从传统方案的 20-40% 提升到接近 100%。

三、核心推理优化技术

Continuous Batching

请求粒度的动态调度，完成一个请求立即插入新请求，无需等待整个批次结束。vLLM 实现了真正的 Per-Request 级批处理，最大化 GPU 利用率。

Chunked Prefill

将长 Prompt 的预填充阶段切分为多个 Chunk，与 Decode 阶段交错执行，避免 Prefill 长时间独占 GPU 导致 Decode 请求的 TTFT 飙升。

CUDA Graph

将一组 GPU 内核调用编译为 CUDA Graph，消除内核启动开销。支持 Piecewise 和 Full 两种模式，在短序列场景下吞吐提升显著。

Prefix Caching

按 Block 级别缓存共享前缀（System Prompt、Few-shot Example），避免重复计算 KV Cache。多轮对话中历史消息自动命中缓存。

Speculative Decoding

用小模型草稿后大模型验证的多 Token 并行生成策略。支持 N-gram、Suffix、EAGLE（Draft 模型）、Medusa 等多种方案。

Disaggregated Prefill/Decode

将 Prefill 和 Decode 部署到不同 GPU 集群，Prefill 集群优化计算吞吐，Decode 集群优化 KV Cache 容量，支持跨节点 KV Cache 传输。

3.1 内存管理策略

vLLM 的 Block Manager 负责所有 KV Cache 的分配、释放和共享管理：

概念说明
Logical Block序列维度的逻辑块视图，以 $[seq\_len/block\_size]$ 递增
Physical BlockGPU 显存中的实际地址块，通过 Block Table 映射
Block Table逻辑块到物理块的映射表，每个序列独立维护
Block Pool全局空闲块池，调度器负责分配与回收
Copy-on-Write共享块在写入前复制，保证序列独立性

3.2 多级量化支持

vLLM 支持业界最广泛的量化方案：FP8（原生 H100/H200 支持）、MXFP8/MXFP4（Microscaling 格式）、NVFP4（NVIDIA 4-bit）、INT8/INT4、AWQ/GPTQ（权重仅量化）、GGUF（CPU 友好）、TorchAO（PyTorch 原生量化）。MoE 模型的稀疏计算也可受益于 FP8 权重和激活量化。

四、Qwen 推理部署实践

vLLM 对 Qwen 全系列模型（Qwen → Qwen1.5 → Qwen2 → Qwen2.5 → Qwen3 → Qwen3.5 → Qwen3.6）提供原生支持，内置对应的对话模板和模型架构适配。

4.1 基础推理：单卡部署 Qwen3-4B

vLLM 单卡推理 Qwen3-4B
# 安装 pip install vllm # OpenAI 兼容 API 服务 CUDA_VISIBLE_DEVICES=0 \ vllm serve Qwen/Qwen3-4B-Instruct-2507 \ --port 8000 \ --tensor-parallel-size 1 \ --gpu-memory-utilization 0.9 \ --max-model-len 32768
Python 客户端调用
from openai import OpenAI client = OpenAI(base_url="http://localhost:8000/v1") response = client.chat.completions.create( model="Qwen/Qwen3-4B-Instruct-2507", messages=[ {"role": "system", "content": "你是 Qwen3 助手"}, {"role": "user", "content": "解释 PagedAttention 的原理"} ], temperature=0.7, max_tokens=2048 ) print(response.choices[0].message.content)

4.2 KV Cache 优化：Prefix Caching 加速多轮对话

多轮对话中，历史消息是共享前缀。启用 Prefix Caching 后，第二轮起 System Prompt 和历史对话的 KV Cache 直接复用：

Qwen3-72B 多轮对话（3× 加速）
CUDA_VISIBLE_DEVICES=0,1,2,3 \ vllm serve Qwen/Qwen3-72B-A27B \ --tensor-parallel-size 4 \ --enable-prefix-caching \ --max-model-len 65536 \ --gpu-memory-utilization 0.95

4.3 多卡分布式推理

对于大参数模型，使用 Tensor Parallelism 将模型分片到多 GPU：

Qwen3-235B 4×H100 分布式推理
CUDA_VISIBLE_DEVICES=0,1,2,3 \ vllm serve Qwen/Qwen3-235B-A47B \ --tensor-parallel-size 4 \ --max-model-len 131072 \ --gpu-memory-utilization 0.9 \ --quantization fp8 \ --enable-prefix-caching

4.4 Speculative Decoding 加速

使用小模型作为草稿模型加速大模型生成：

Qwen3-72B + Qwen3-4B 投机解码
CUDA_VISIBLE_DEVICES=0,1,2,3 \ vllm serve Qwen/Qwen3-72B-A27B \ --tensor-parallel-size 4 \ --speculative-model Qwen/Qwen3-4B-Instruct-2507 \ --num-speculative-tokens 5 \ --ngram-prompt-lookup-max 4 \ --spec-decoding-acceptance-method draft_model

4.5 离线批量推理

Python SDK 提供离线批处理接口，适合数据批量处理场景：

批量推理 Qwen2.5-7B
from vllm import LLM, SamplingParams llm = LLM( model="Qwen/Qwen2.5-7B-Instruct", tensor_parallel_size=1, gpu_memory_utilization=0.9, max_model_len=4096, ) sampling_params = SamplingParams( temperature=0.7, top_p=0.9, max_tokens=1024 ) prompts = ["解释 RNN", "什么是 Attention", "什么是 Transformer"] outputs = llm.generate(prompts, sampling_params) for output in outputs: print(output.outputs[0].text)

六、总结

vLLM 通过 PagedAttention 开创性地将操作系统虚拟内存管理引入 LLM 推理，解决了长期困扰大模型服务的 KV Cache 碎片化问题。其核心优势包括：

  • 显存效率：PagedAttention 将 KV Cache 利用率从 20-40% 提升到近 100%，相同硬件可服务更多并发请求
  • 吞吐性能：Continuous Batching + CUDA Graph + FlashAttention 三板斧确保高吞吐
  • 量化广泛：FP8/INT4/AWQ/GPTQ/GGUF 等全栈量化支持，覆盖从数据中心到边缘设备
  • Qwen 完整支持：Qwen 系列全模型原生适配（Qwen → Qwen3.6），内置对话模板和架构识别
  • 生态成熟：82,000+ GitHub Stars，200+ 模型架构支持，广泛的生产部署验证

vLLM 已成为 LLM 推理领域的事实标准之一。对于使用 Qwen 系列模型的推理部署场景，vLLM 提供了从单卡到大规模分布式集群的完整解决方案。
