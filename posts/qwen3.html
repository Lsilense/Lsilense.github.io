Qwen3 技术解析：统一思考框架与细粒度 MoE

📅 2026 年 6 月 13 日 🏷️ Qwen

引言

2025 年 5 月，阿里云 Qwen 团队发布了 Qwen3——Qwen 模型家族的最新版本。与 Qwen2.5 相比，Qwen3 在架构、训练和推理三个层面做出了关键升级：将思考模式（Thinking Mode）与非思考模式（Non-Thinking Mode）统一到单一模型框架中，用户无需切换模型即可按需控制推理深度；引入了 Thinking Budget 机制，允许用户为推理过程分配可变的 Token 预算；在 MoE 架构上沿用了细粒度专家分割设计，并增加 QK-Norm 以保证训练稳定性。

Qwen3 系列覆盖了从 0.6B 到 235B 的广泛规模，包含 6 个密集模型和 2 个 MoE 模型。旗舰模型 Qwen3-235B-A22B（235B 总参数，22B 激活参数）在 Thinking 模式下以 AIME'24 85.7% 的成绩超越 DeepSeek-R1（79.8%），在 Non-Thinking 模式下也全面超越 Qwen2.5-72B-Instruct。全部模型以 Apache 2.0 协议开源。本文将从架构设计、多语言扩展、统一思考框架和后训练管线四个方面深入解析 Qwen3。

架构设计

密集模型架构

Qwen3 密集模型的架构与 Qwen2.5 基本一致，沿用了经过验证的关键设计：

  • GQA（Grouped Query Attention）：分组查询注意力，降低 KV Cache 开销
  • SwiGLU：门控线性单元配合 Swish 激活
  • RoPE（Rotary Position Embedding）：旋转位置编码
  • RMSNorm：均方根归一化，配合 Pre-Normalization 结构

相比 Qwen2 的两处关键改进：移除了 QKV-bias，并引入了 QK-Norm 来稳定训练。

MoE 架构

Qwen3 的 MoE 模型沿用了 Qwen2.5-MoE 的细粒度专家分割（Fine-Grained Expert Segmentation）设计。旗舰模型 Qwen3-235B-A22B 配置为 128 个路由专家，每个 Token 激活 8 个。与 Qwen2.5-MoE 的关键区别在于去除了共享专家——所有 128 个专家均为路由专家，通过 Top-8 门控选择激活。

MoE 模型共享密集模型的基础架构（GQA、SwiGLU、RoPE、RMSNorm），仅在前馈网络部分替换为专家路由层。这种设计使得 MoE 模型在保持与密集模型相同推理框架兼容性的同时，大幅扩展了模型容量。

图 1：Qwen3-235B-A22B MoE Block 架构 — 128 个细粒度专家（无共享专家），每 Token Top-8 激活，基础架构包含 GQA + QK-Norm + RoPE

# Qwen3 MoE 路由示意
def qwen3_moe_forward(x, router, experts, top_k=8):
    # x: [batch, seq_len, d]
    scores = router(x)                         # [batch, seq, 128]
    top_scores, top_indices = topk(scores, top_k)
    # 加权融合选中专家输出
    output = 0
    for k in range(top_k):
        expert_out = experts[top_indices[k]](x)
        output += expert_out * softmax(top_scores[..., k])
    return output

多语言扩展：从 29 到 119 种语言

Qwen3 在多语言支持上做出了显著提升，从 Qwen2.5 的 29 种语言扩展至 119 种语言和方言。在预训练数据构建上采用了多步骤策略：

  1. OCR 文本提取：使用 Qwen2.5-VL 模型对海量 PDF 类文档进行文字识别
  2. 质量精炼：利用 Qwen2.5 对识别结果进行清洗和重写，获得数万亿高质量 Token
  3. 合成数据生成：使用 Qwen2.5、Qwen2.5-Math、Qwen2.5-Coder 生成教科书、问答、代码等合成数据
  4. 多语言扩展：引入额外的多语言数据，覆盖范围从 29 种扩展到 119 种

在多语言评测上，Qwen3 在 MT-AIME2024（55 种语言的数学推理）上达到 80.8%，显著超过 DeepSeek-R1（73.5%），体现了在多语言推理上的领先优势。

核心创新：统一思考框架

Qwen3 最核心的创新在于将思考模式（Thinking）和非思考模式（Non-Thinking）融合到单一模型中。在此之前的范式是：需要推理时使用专门的推理模型（如 DeepSeek-R1、QwQ-32B），需要快速响应时使用对话模型（如 GPT-4o、DeepSeek-V3）。Qwen3 用单一权重覆盖了两种模式。

Thinking Budget：可控的推理深度

除模式切换外，Qwen3 还引入了 Thinking Budget 机制，用户可以为推理过程指定 Token 预算——预算越高，模型可以"思考"得越深入；预算越低，响应越快。实验表明，随着 Thinking Budget 的增加，模型在数学和代码任务上的表现持续提升。

模式切换机制

通过 Chat Template 和特定标志位控制：

模式 用户输入 模型输出
思考模式 {query} /think <think>...推理过程...</think>
...最终响应...
非思考模式 {query} /no think <think></think>
...直接响应...

在 Hugging Face 的 Tokenizer 中，思考模式默认启用，可以通过 enable_thinking=False 参数关闭。

Stage 1：Long-CoT Cold Start

收集涵盖数学、代码和逻辑推理的长思维链数据，通过 SFT 让模型学会结构化推理过程。此阶段为后续 RL 提供了良好的初始化起点。

Stage 2：Reasoning RL

使用 GRPO（Group Relative Policy Optimization）对模型进行推理强化学习。在数学和代码任务上使用基于规则的正确性奖励。Qwen3-235B-A22B 在此阶段仅用 170 步 RL 就将 AIME'24 从 70.1 提升到 85.1，展现了高效的 RL 收敛特性。

Stage 3：Thinking Mode Fusion

将非思考能力融合到已具备推理能力的模型中。通过精心设计的 SFT 数据（包含 Thinking 和 Non-Thinking 两种格式）和监督微调实现双模式兼容。Thinking 数据通过拒绝采样从 Stage 2 模型生成，确保推理能力不退化。

Stage 4：General RL

覆盖 20+ 任务的通用强化学习，使用三类奖励信号：

  • 基于规则的奖励：数学验证、代码编译测试
  • 模型奖励：用于偏好对齐和风格控制
  • 环境反馈：Agent 任务中的真实环境执行结果

Strong-to-Weak 蒸馏

对于轻量级模型（如 Qwen3-30B-A3B、Qwen3-14B 等），Qwen3 采用 Strong-to-Weak Distillation 策略，而非逐一执行完整的四阶段训练。具体来说，直接将旗舰模型的输出 Logits 蒸馏到小模型上，同时保留对推理过程的细粒度控制。

这种方法带来了三重收益：

  • Pass@1 更高：蒸馏后的模型在单次采样上表现更好
  • Pass@64 更高：模型的探索能力也得到了保留
  • 训练效率极高：仅需四阶段训练的 1/10 GPU 小时

开源与部署

Qwen3 全系列以 Apache 2.0 协议开源：

  • Hugging Face：huggingface.co/Qwen · 所有 8 个模型权重
  • ModelScope：modelscope.cn/organization/qwen
  • GitHub：github.com/QwenLM/Qwen3
  • 推理框架：通过 vLLM 和 SGLang 支持部署。Qwen3-30B-A3B（3B 激活）可在消费级 GPU 上高效运行，Qwen3-235B-A22B 推荐多 GPU 部署
  • Hugging Face Transformers：自近期版本起原生支持，使用 enable_thinking=False 控制思考模式

总结

Qwen3 的核心贡献在于统一思考框架的设计，将推理模型与对话模型的能力融合到单一权重中，并通过 Thinking Budget 机制为用户提供了可调节的推理-速度权衡。在架构层面，细粒度 MoE 配合 128 专家和 QK-Norm 设计在 22B 激活参数下实现了超越 DeepSeek-R1（37B 激活）的推理性能，证明了 MoE 容量-效率权衡中的精细设计空间。

多语言扩展至 119 种语言、Strong-to-Weak 蒸馏以 1/10 的 GPU 成本高效生产轻量模型，以及 Apache 2.0 的完全开源协议，使得 Qwen3 成为从云端旗舰到边缘设备的广泛部署选择。
