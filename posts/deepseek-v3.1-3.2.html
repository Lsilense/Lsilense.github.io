DeepSeek-V3.1 / V3.2 技术解析：混合推理与稀疏注意力

📅 2026 年 6 月 14 日 🏷️ DeepSeek

引言

DeepSeek-V3 于 2024 年 12 月问世后，深度求索并未止步。在随后的一年中，V3 系列经历了两次重要迭代——V3.1（2025 年 8 月）和 V3.2（2025 年 12 月），分别在不同方向上拓展了 V3 的能力边界。V3.1 开启了混合推理（Think / Non-Think）的新范式，V3.2 则通过 DSA 稀疏注意力在架构层面实现了突破，并首次在工具使用中集成思考推理。

本文将 V3.1 和 V3.2 放在一起分析，梳理 V3 系列从发布到被 V4 全面重组之间的这条演进路线。

V3.1：混合推理时代的开启

DeepSeek-V3.1 是 V3 系列的第一次重大功能升级，发布于 2025 年 8 月 21 日。与 V3 相比，V3.1 的模型架构几乎没有变化——同样的 61 层结构、同样的 MLA + DeepSeekMoE 配置、同样的 7168 维隐藏层。其核心变化集中在训练后处理和推理范式上。

持续预训练与上下文扩展

V3.1 在 V3 的基础上进行了 840B tokens 的持续预训练，主要目标是将上下文窗口从 128K 进一步扩展并增强模型在长文本场景下的稳定性。架构参数上，V3.1 唯一新增的配置项是 scale_fmt: "ue8m0"——一种 8 位纯指数浮点格式（unsigned 8-bit exponent, 0-bit mantissa），用于 FP8 量化缩放因子。相比标准的 E4/E5 FP8 格式，ue8m0 将全部 8 位用于指数，提供了约 $10^{38}$ 的超大动态范围，使其能够在混合精度训练中更精确地表示各层的量化缩放系数。

混合推理：Think / Non-Think 模式

V3.1 最具标志性的新特性是混合推理（Hybrid Reasoning）。一个模型权重同时支持两种推理模式：

  • Non-Think：标准生成模式，不输出显式推理链，适用于简单对话和查询，对应 API 路由 deepseek-chat
  • Think：在 <think> 标签内输出显式的思维链推理过程，适用于数学、逻辑等复杂任务，对应 API 路由 deepseek-reasoner

这一设计后来成为 DeepSeek 后续所有模型（V3.2、V4）的标准能力。值得注意的是，Think/Non-Think 模式的切换完全由 API 级别控制，不依赖模型权重的差异——同一权重在不同 prompt 模板下展现出完全不同的推理行为。这种 unified checkpoint 的设计大幅降低了部署复杂度。

Agent 与工具调用增强

V3.1 在后训练阶段针对 Agent 场景做了专门优化，提升了工具调用和多步骤 Agent 任务的执行能力。同时，V3.1 开始支持 Anthropic API 格式和严格的函数调用模式（Beta），为开发者提供了更灵活的集成方式。

此外，V3.1 还更新了分词器和对话模板，改进了多语言场景下的语言一致性表现。

V3.2：DSA 稀疏注意力架构

2025 年 9 月 29 日，DeepSeek 发布了 V3.2-Exp（实验版），率先引入 DeepSeek Sparse Attention（DSA）稀疏注意力机制。三个月后的 12 月 1 日，V3.2 正式版发布，将 DSA 与全新的 Agent 训练方法论结合，同时推出了极致推理版本 V3.2-Speciale。这是 V3 系列在架构层面的唯一一次实质性改动。

DSA 的核心思想

DSA（DeepSeek Sparse Attention）是一个两阶段的稀疏注意力机制，其核心设计是：用一个轻量的 Lightning Indexer 为每个查询 Token 筛选出最相关的 K 个前缀 Token，然后主模型（MLA）仅对这 K 个 Token 执行注意力计算。这本质上是将注意力计算从序列长度的一次方复杂度进一步降低到常数 Top-K 复杂度。

DSA 的核心公式为：

$$ \mathbf{I}_{t,s} = \sum_{j=1}^{H^I} w^I_{t,j} \cdot \text{ReLU}(\mathbf{q}^{I^\top}_{t,j} \mathbf{k}^I_s) $$

其中 $H^I = 64$ 是 Indexer 的注意力头数，$w^I_{t,j}$ 是每个头的可学习重要性权重。$\mathbf{I}_{t,s}$ 表示查询 $t$ 与源 Token $s$ 之间的相关性分数。最终，仅保留分数最高的 $K = 2048$ 个位置参与主 MLA 注意力计算：

$$ \text{Attn}_{\text{DSA}}(\mathbf{q}_t, \mathbf{K}, \mathbf{V}) = \sum_{s \in \text{TopK}(\mathbf{I}_{t,:})} \text{Softmax}\left(\frac{\mathbf{q}_t^\top \mathbf{k}_s}{\sqrt{d_h}}\right) \mathbf{v}_s $$

Indexer 的蒸馏式训练

Lightning Indexer 的训练过程类似于知识蒸馏。主模型 MLA 的注意力分布 $A_h[t,:]$ 跨所有 128 个注意力头求和并做 L1 归一化，作为 Indexer 的学习目标：

$$ p_{t,:} = \frac{\sum_{h=1}^{128} \mathbf{A}_h[t,:]}{\left\|\sum_{h=1}^{128} \mathbf{A}_h[t,:]\right\|_1} $$

Indexer 的损失函数为每个位置的 KL 散度之和：

$$ \mathcal{L}^I = \sum_{t=1}^{T} D_{\text{KL}}(p_{t,:} \parallel \text{Softmax}(\mathbf{I}_{t,:})) $$

训练期间主模型参数完全冻结，Indexer 使用 MLA 的 MQA（Multi-Query Attention）模式——64 个 Indexer 查询头共享一个 KV 头——以保持轻量。Indexer 的 KV Cache 使用 FP8（e4m3fn）格式存储，包含旋转矩阵（Hadamard transform）用于激活值的均衡化。训练完成后，Indexer 的权重与主模型一同部署，在推理时充当高效的 Token 选择器。

# DSA 推理时 Top-K 选择（简化）
def dsa_attention(q, k, v, indexer, top_k=2048):
    # q, k, v: [batch, seq_len, dim]
    # Step 1: Indexer 计算全序列分数
    index_scores = indexer(q, k)          # [batch, seq_len, seq_len]
    # Step 2: 选择 Top-K
    topk_indices = index_scores.topk(top_k, dim=-1)[1]
    # Step 3: 构建稀疏掩码
    index_mask = full(-inf).scatter_(-1, topk_indices, 0)
    # Step 4: 主模型 MLA 仅对选中位置计算
    attn_scores = mla_scores(q, k) + index_mask
    return softmax(attn_scores) @ v

稀疏比例与序列长度

DSA 的一个关键特性是 Top-K 为常数（$K = 2048$），不随序列长度变化。这意味着有效稀疏比例随序列长度动态变化：

  • $8K$ 上下文：$2048 / 8192 = 25\%$ 的 Token 参与注意力计算
  • $32K$ 上下文：$2048 / 32768 \approx 6.25\%$
  • $128K$ 上下文：$2048 / 131072 \approx 1.56\%$

虽然相比 V4 的 CSA/HCA 设计（仅 27% 的 FLOPs），DSA 的激进程度相对温和，但在 V3 原版 MLA 的基础上引入 DSA 已足以在长序列场景下带来可观的推理加速和 KV Cache 节省。

V3.2 的 Agent 训练方法论

V3.2 正式版在 DSA 架构之上，引入了一套全新的大规模 Agent 训练数据合成方法论。这是 V3.2 相对于 V3.2-Exp 实验版的核心区别所在。

该方法的规模令人印象深刻：覆盖 1,800 多个模拟环境，生成了 85,000 多条复杂指令。这些环境涵盖 Web 浏览、代码执行、API 调用、文件系统操作、数据库查询等场景。每条指令在一个或多个环境中执行，产生交织了思考链（Chain-of-Thought）和工具调用的训练轨迹。

结果，V3.2 成为首个在工具使用中集成思考（Thinking in Tool-Use）的模型。模型可以在调用工具前进行推理规划，在执行过程中根据工具返回结果动态调整策略——这种能力在以往的工具调用模型中并不存在。V3.2 同时支持在 Think 和 Non-Think 两种模式下使用工具，为开发者提供了灵活的权衡空间。

V3.2-Speciale：极致推理版本

与 V3.2 正式版一同发布的还有 V3.2-Speciale，一个面向极致推理场景的强化版本。Speciale 基于相同的 DSA + MLA 基座，但在推理时投入了更多计算资源（可能涉及更多的专家激活、更长的思考链和重复采样），使其在数学竞赛和编程竞赛中达到了金牌水平：

  • IMO 2025（国际数学奥林匹克）— 金牌水平
  • IOI 2025（国际信息学奥林匹克）— 金牌水平
  • CMO（中国数学奥林匹克）— 金牌水平
  • ICPC 世界总决赛— 金牌水平

DeepSeek 官方宣称 V3.2 的综合性能对标 GPT-5 级别，Speciale 版本对标 Gemini 3.0 Pro。Speciale 仅通过 API 提供，不支持工具调用，是纯粹为推理评测打造的极致版本。

从 V3 到 V4 的桥梁

回顾 V3 系列的演进，可以看出 DeepSeek 的探索方向逐渐清晰：V3 验证了 MLA + DeepSeekMoE 基座的有效性；V3.1 在无架构变化的前提下探索了混合推理的可行性；V3.2 通过 DSA 试探了稀疏注意力在长上下文场景下的潜力。

这些探索最终在 V4 中汇聚成一次完整的架构重构——DSA 的 Token 选择思想演化成了 V4 的 Lightning Indexer，混合推理模式被 V4 继承并扩展为三重模式（Non-Think / Think High / Think Max），V3.2 的 Agent 训练方法论也在 V4 中进一步规模化，形成了独立培养 + 统一融合的双阶段训练范式。

V3 系列（V3 → V3.1 → V3.2）构成了 DeepSeek 从 MLA 时代到 V4 全面重构之间的关键过渡阶段——旧架构的边界在哪里，新架构需要解决什么问题，都在这个阶段中被清晰地定义了出来。
