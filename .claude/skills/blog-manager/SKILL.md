# Blog Manager — Lsilense.github.io

管理个人 AI/ML 博客 Lsilense.github.io。涵盖内容操作、站点维护，并通过操作后反思持续自我改进。

## 进入流程

1. 先读本文件。
2. 读项目根目录的 `CLAUDE.md`，了解项目结构和约定。
3. 如果 `reflections/` 目录存在，读取最近 **5 条**反思记录（按文件名排序），检查是否有反复出现的问题。如果同一改进点出现 3 次以上，视为已确认的改进方向（详见下方「自我更新」）。

## 操作指南

### 1. 新建文章

**步骤：**

1. 读取 `posts.json` — 了解字段结构（`id`, `title`, `date`, `excerpt`, `tags`）和已有文章。
2. 确定新文章的 `id`（kebab-case 短横线命名，如 `llama-architecture`）。
3. **内容生成：** 如果用户提供了主题或要点，生成完整的文章。博客专注方向：主流模型（LLM/MoE/多模态）、模型训练（预训练/微调/分布式）、模型推理（vLLM/TensorRT/KV Cache）、RAG、Agent。默认用中文写作（除非用户另有要求）。如果用户提供的外文内容，翻译成中文。
4. 创建 `posts/<id>.html` — 参考已有文章模板。需要复制的关键元素：
   - `<head>` 部分（字体、CSS、主题脚本）
   - 共享 `<nav>`，正确设置 "文章" 链接的 `.active` 类
   - `<div class="post-detail">` 包裹文章内容
   - 正文使用 `.p-body` 类，标准 HTML 结构（h2、h3、p、pre code、blockquote、ul/ol）
   - 共享 `<footer>`
   - `<script src="../js/main.js"></script>`
5. 在 `posts.json` 中添加条目 — 日期格式 `YYYY-MM-DD`。
6. **验证：** 确保文件名与 `posts.json` 中的 `id` 一致。

### 2. 新建项目

**步骤：**

1. 读取 `projects.json` — 了解字段结构（`id`, `icon`, `title`, `url`, `excerpt`, `description`, `tags`）。
2. 创建 `projects/<id>.html` — 参考已有项目模板。
3. 在 `projects.json` 中添加条目。

### 3. 修改已有内容

- **文章：** 修改 `posts/<id>.html` 更新正文；修改 `posts.json` 更新元数据（标题、日期、摘要、标签）。
- **项目：** 修改 `projects/<id>.html` 更新详情；修改 `projects.json` 更新元数据。
- **其他页面**（research、tech-stack 等）：直接编辑对应的 `.html` 文件。
- **posts.json / projects.json 的修改** — 首页和列表页在运行时读取这些 JSON，无需构建步骤，下次刷新页面即生效。

### 4. 修改样式 / 布局

- **CSS：** 所有样式在 `css/style.css`。通过 `:root`（深色模式）和 `[data-theme="light"]` 上的 CSS 自定义属性实现主题。
- **布局：** 导航栏和页脚在所有 `.html` 文件中重复。如果修改导航/页脚结构，必须同步更新根目录下**每一个** `.html` 文件。
- **新增页面：** 遵循相同模式 — 包含 `<head>`、共享 `<nav>`（将对应链接设为 `.active`）、内容区域、`<footer>`。在所有已有 `.html` 文件的导航中添加新页面的链接。

### 5. 文章生成 / 翻译

**生成：**
- 技术博客风格：清晰、有结构，适当包含代码示例。
- 使用准确的中文 AI/ML 术语。
- 用 h2 组织章节，包含代码块（`<pre><code>`），开头写一段简要介绍。

**翻译：**
- 将提供的内容翻译成中文（除非另有要求）。
- 将技术术语转换为常见中文译法（如 "fine-tuning" → "微调"）。
- 保留代码块、URL 和专有名词不变。

## 反思机制

**每次**操作完成后，必须写一条反思记录，记录做了什么以及可以如何改进。

### 存放位置

`.claude/skills/blog-manager/reflections/<日期>-<任务类型>-<简述>.md`

示例：`2026-06-11-new-post-deepseek.md`

### 格式

```markdown
## 反思：<日期> — <任务类型>

### 任务
做了什么以及为什么做。

### 做得好
- 哪些步骤很顺畅。

### 可以改进
- 痛点、错误、或导致额外工作的地方。

### 改进措施
- 下次如何避免的具体步骤。
```

### 自我更新

**何时更新 SKILL.md：**

写完反思后、结束对话前，扫描最近 10 条反思记录。如果同一改进措施（或高度相似的变体）出现 **3 次及以上**，则自动更新 SKILL.md，将修复步骤固化到工作流程中。

**如何更新：**

- 在对应操作章节中补充缺失的步骤。
- 如果改进影响面较大，新增一个章节或备注说明。
- 在反思中注明 SKILL.md 已更新：`SKILL.md 已更新：在 <操作> 后新增 <步骤>。`

**不更新的情况：**

- 一次性问题（如文章标题打错字 — 直接改掉即可）。
- 不太可能重复的用户偏好变化。
- 已有步骤覆盖但操作时没执行的内容。
